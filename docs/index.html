The business problem

How can enterprises automate repetitive order support requests while keeping execution reliable, escalation appropriate, and AI decisions visible?

Repetitive volume

"Where is my order?" and similar questions follow the same steps every time, yet they consume human support capacity.

Sensitive actions

Answering means reading customer and order data, and some requests create records. An AI agent must not guess, skip a check, or reveal another customer's order.

Trust and oversight

Support leaders need to see what the agent did and why, and customers who need a person must reach one with context.

Technical execution

How the Solution Works

Each layer has one job. The model interprets the customer; code decides what is allowed and does the work; data comes from systems of record; people handle what the agent should not.

AI interpretation

A router and subagents in Agent Script. The model works out intent and chooses an action, only from the actions available at that moment.

Deterministic logic

Apex verifies the customer, reads order status and opens Cases; a Flow decides return eligibility. Inputs come from the verified record, not from the model.

Enterprise data

Orders are read from Salesforce records with the agent user's permissions. Policy answers come from a Data Cloud search over the policy documents.

Human escalation

A handoff Case records the reason and a summary, and a routing Flow sends the chat to the service queue in Omni-Channel.

Why the separation matters

Language models are good at understanding what a customer means and unreliable at following a rule every time. So the rules live in code: the order tools do not exist for the model until verification succeeds, their inputs come from the verified record rather than from what the customer typed, and the return window is enforced by a Flow. If the model misreads a request, the worst case is a wrong question or a handoff, not a wrong refund or someone else's order.

Engineering decisions

Engineering Decisions

Implemented

Sensitive operations are gated in code

  • Order, Case and return actions are only available after Apex returns verified = true.
  • Their inputs are bound to the verified order and email, not filled in by the model.
  • Apex queries run in user mode and re-check that the email owns the order.
  • Three failed checks hand off; five on one order lock it for 30 minutes across chats.

Found and fixed: the agent once replied "details don't match" without running the check. A live regression went from 0/5 to 5/5 after the fix.

Implemented

Structured data by tool, documents by retrieval

  • Order status comes from an Apex lookup on the order record, so the agent cannot invent a tracking number.
  • Policy questions go to a Data Cloud Data Library (hybrid search over the policy documents). The agent must search before answering and decline if nothing covers it.

Policy eval: 12/12 answered and 4/4 out-of-scope questions declined (English, agent v11).

Implemented

Exceptions end in a clear next step

  • Failed verification gets one fixed sentence that never says which detail was wrong.
  • Unsupported questions are declined with an offer of a person; off-topic requests are redirected.
  • Escalation opens a handoff Case with a summary before routing the chat.

Proposed improvement A retrieval outage currently looks like a normal "not covered" reply, and a handoff with nobody online waits in the queue. Production needs an outage message, an alert, and an offline path.

Business impact

From AI Capability to Business Value

Support teams spend a large share of their time on repetitive order questions, status requests and exceptions. That work carries operational cost and takes capacity away from the cases that need judgment. This prototype automates the repetitive path end to end, enforces the rules in code, and hands the rest to people with context, so the value can be measured rather than assumed.

Proposed production KPIs These are the measures I would agree with a customer before launch. They have not been measured: the prototype has no production traffic.

Automated Resolution Rate

Share of eligible inquiries resolved without a person.

Measure from Agentforce session tracing: sessions that end without the escalation path, over eligible sessions. This build already queries session tracing.

Average Handling Time

Average time from first message to resolution or handoff.

Measure from session and turn timestamps in session tracing, compared with the same contact types handled by people.

Escalation Accuracy

Share of conversations escalated, or not, according to the agreed rules.

Measure against a labeled set: explicit requests for a person and three failed verifications must escalate; answerable questions must not.

Cost per Resolution

Average cost to resolve one inquiry.

Measure Agentforce consumption for resolved sessions over the number resolved, against the loaded cost of a human-handled contact.
